# Комплексный план исправлений и доработок (Release 1.2: Polish & Ergonomics)

Архитектурный и инженерный план доработок Omega Cloud. Составлен по итогам анализа кодовой базы и интерактивного проектирования (`/grill-me`). План разбит на 4 независимых этапа с четкими критериями верификации для каждого шага. В конце каждого этапа и по завершении всех работ предусмотрена фиксация изменений и отправка в удаленный репозиторий GitHub (`git push origin master`).

---

## Ключевые архитектурные решения (согласованные в ходе /grill-me)

1. **Валидация емкости нод и квот (Исправление ошибки 400):**
   - Бэкенд валидирует емкость активных нод по **фактически занятому месту** (`UsedBytes` / `UsedQuotaBytes`), а не по сумме виртуально выделенных квот пользователей (`AllocatedQuotaBytes`). Это открывает поддержку безопасного оверселлинга (overprovisioning).
   - Для Мастер-ноды (`LocalDisk`) внедряется динамический опрос реального диска хоста через `DriveInfo` (`TotalSize` и `AvailableFreeSpace`), исключая захардкоженные 10 ТБ из сидера.
   - В админ-панели при редактировании ноды и пользователя отображается физический объем диска (Всего и Свободно) с человекочитаемым выбором единиц (ГБ / ТБ). Запрещается выставлять емкость ноды больше размера физического диска.

2. **Двустороннее копирование (Personal ⇄ Shared Space):**
   - Реализуется через дедупликацию блобов: новый `FileItem` ссылается на существующий `StorageBlob`, увеличивая `blob.ReferenceCount++`. Физический файл на диске не дублируется.
   - Из личного диска в общий: контекстное меню, тулбар групповых действий (Bulk Bar), перетаскивание мыши (Drag & Drop) на пункт «Общий раздел» в сайдбаре. Поддерживается выбор целевой папки в Общем разделе.
   - Из общего раздела в личный: кнопка «Сохранить в личный диск» с выбором папки назначения в личном диске.

3. **Десктопный Drag & Drop и множественное выделение:**
   - Снятие ложной блокировки `isTouchDevice` при случайных touch-событиях.
   - Изоляция событий на дочерних элементах (`pointer-events: none` во время D&D) для исключения мерцания `dragleave`.
   - Добавление `event.stopPropagation()` на сбросе в папку, чтобы событие не всплывало на фоновую загрузку файлов окна (`app-shell`).
   - Чекбоксы (галочки) выбора на карточках сетки (Grid) и отдельная колонка с чекбоксами и кнопкой «Выбрать все» в таблице (List).
   - Ликвидация дублирующейся мобильной нижней шторки на десктопе: оставляем только одну элегантную плавающую стеклянную панель Bulk Action Bar.

4. **Продвинутое модальное окно выбора области поиска:**
   - Замена стандартного селектора на модальное окно с интерактивным деревом папок: выбор области («Везде», «Личный диск», «Общий раздел», либо конкретные выбранные папки).

5. **Кастомные стеклянные выпадающие меню (Glass Dropdown):**
   - Замена всех нативных HTML-тегов `<select>` на единый стилизованный компонент `app-glass-dropdown` с поддержкой анимаций, клавиатуры и закрытия по клику вне элемента.

6. **Единый визуальный стиль и брендинг:**
   - Выравнивание геометрии шапки и сайдбара во всех разделах (Личный диск, Общий раздел, Админка, Дашборд): фиксированная высота бренда 64px, единый градиентный бейдж логотипа, идентичные отступы.
   - Возврат пунктов «Избранное» и «Корзина» в сайдбар общего раздела.
   - Кнопка «Перейти в общий раздел» на экране авторизации (`/login`).
   - Сброс кеша фавикона в браузере (оптимизация веса и версионирование `favicon.ico?v=2`).

## Этап 1. Бэкенд: Квоты, телеметрия физического диска и валидация нод

> **Цель этапа:** Устранить ошибку HTTP 400 при редактировании емкости нод, внедрить динамический опрос реального диска сервера через `DriveInfo`, поддержать оверселлинг квот и защитить систему от переполнения физического диска.

### Задачи:

1. **Рефакторинг валидации в `NodeService.cs`:**
   - В методе `UpdateNodeAsync`:
     - Заменить блокирующую проверку `totalAllocatedQuota > totalActiveCapacity` на проверку фактического использования:
       ```csharp
       var totalUsedBytes = await _dbContext.FileItems
           .Where(f => !f.IsDeleted)
           .SumAsync(f => f.SizeBytes, ct);

       if (totalUsedBytes > totalActiveCapacity)
       {
           throw new ValidationException(
               $"Невозможно уменьшить емкость нод ниже фактически занятого объема файлов ({totalUsedBytes} байт).");
       }
       ```
     - Добавить проверку емкости для Master Local Storage: емкость ноды не может превышать физический размер диска хоста.

2. **Телеметрия локального диска для Master Storage Node (`LocalDisk`):**
   - Внедрить сервис / хелпер `DiskTelemetryProvider`:
     - Определение физического пути монтирования хранилища (`Storage:LocalRootPath` или дефолтный каталог).
     - Вызов `DriveInfo` для получения `TotalSize` и `AvailableFreeSpace`.
   - В `NodeService` при получении списка нод (`GetAllNodesAsync`) и информации о локальной ноде динамически обновлять/возвращать актуальные физические `TotalSpaceBytes` и `AvailableSpaceBytes` локального диска.
   - Обновить сидер `DatabaseSeeder.cs`: при создании дефолтной ноды брать реальные размеры смонтированного диска вместо фиктивных 10 ТБ.

3. **Корректировка валидации в `AdminUserService.cs`:**
   - При создании или изменении квоты пользователя:
     - Разрешить сумму квот пользователей больше емкости нод (оверселлинг).
     - Проверять только, чтобы новая квота одного пользователя не была отрицательной и не превышала суммарную физическую емкость активных нод хранилища.

4. **Тесты:**
   - Написать интеграционные тесты:
     - Успешное изменение емкости ноды при наличии пользователей с суммарной квотой, превышающей емкость ноды (если реальные файлы помещаются).
     - Ошибка валидации при попытке сжать ноду ниже фактически занятого объема файлов.
     - Корректная отдача телеметрии физического диска для локальной ноды.

## Этап 2. Новые функции VFS: Двустороннее копирование (Personal ⇄ Shared)

> **Цель этапа:** Реализовать высокопроизводительное копирование файлов и папок между личным пространством и общим разделом без дублирования физических блобов данных на диске.

### Задачи:

1. **Эндпоинты бэкенда для копирования в VFS (`FilesController` / `SharedController`):**
   - `POST /api/v1/files/copy-to-shared`:
     - Принимает `fileIds: Guid[]`, `folderIds: Guid[]`, `targetSharedFolderId: Guid?`.
     - Требует авторизации пользователя (`[Authorize]`).
     - Создает копии `FileItem` с флагом `IsShared = true`.
     - Привязывает созданные файлы к существующим `StorageBlobId` и увеличивает `blob.ReferenceCount++`.
     - Рекурсивно создает копии папок в дереве общего раздела (`IsShared = true`).
     - Разрешает коллизии имен (авто-суффикс `(1)` при совпадении имени в целевой папке).
     - Рассылает SignalR-уведомление `DirectoryChanged` для общего раздела.
   - `POST /api/v1/shared/save-to-personal`:
     - Принимает `fileIds: Guid[]`, `folderIds: Guid[]`, `targetFolderId: Guid?`.
     - Требует авторизации пользователя.
     - Создает личные копии в диске пользователя (`IsShared = false`, `UserId = currentUserId`).
     - Проверяет личную квоту автора: добавляет размер копируемых файлов к `user.UsedQuotaBytes`. Если квота превышена — возвращает 400 с понятной ошибкой.
     - Ссылается на те же `StorageBlobId` с `blob.ReferenceCount++`.
     - Рассылает SignalR-уведомление для личного диска пользователя.

2. **Реализация в бизнес-логике (`FileService.cs` / `SharedService.cs`):**
   - Метод `CopyToSharedAsync(IEnumerable<Guid> fileIds, IEnumerable<Guid>? folderIds, Guid? targetSharedFolderId, Guid userId, CancellationToken ct)`.
   - Метод `SaveToPersonalAsync(IEnumerable<Guid> fileIds, IEnumerable<Guid>? folderIds, Guid? targetFolderId, Guid userId, CancellationToken ct)`.
   - Аудит операций в `AuditService`: логирование событий `FilesCopiedToShared` и `FilesSavedToPersonal`.

3. **Интеграция с клиентом Angular (`ApiService.ts`):**
   - Добавить методы `copyToShared(fileIds, folderIds, targetSharedFolderId)` и `saveToPersonal(fileIds, folderIds, targetFolderId)`.

4. **Тесты:**
   - Интеграционные тесты копирования файла в Shared: проверка создания `FileItem`, неизменности дискового блоба, инкремента `ReferenceCount`.
   - Тест на запрет сохранения из Shared при исчерпании личной квоты.
   - Тест рекурсивного копирования папки со вложенными файлами.

## Этап 3. Десктопный UX: D&D, чекбоксы мультивыделения, окно выбора поиска и фикс тулбаров

> **Цель этапа:** Довести интерактивность диска до уровня полноценного проводника: исправить перетаскивание файлов мышью, устранить баг двух панелей действий, добавить чекбоксы выбора элементов и модалку выбора целевых папок для поиска.

### Задачи:

1. **Исправление Drag & Drop в папки диска:**
   - В `file-grid.component.ts` и `file-list.component.ts`:
     - Удалить блокировку `this.isTouchDevice = true` по одиночному touch-событию, которая навсегда выключала `[draggable]`.
     - Для содержимого карточек папок и файлов (`.folder-icon`, `.folder-info`, `.file-preview`, `.file-footer`) задать `pointer-events: none` во время перетаскивания, устранив ложные срабатывания `dragleave` при движении курсора внутри карточки.
     - Добавить `event.stopPropagation()` в обработчиках `onFolderDragOver` и `onFolderDrop`, чтобы событие сброса не всплывало на оверлей загрузки файлов всего окна (`app-shell`).
     - В `onFolderDrop`: помимо передачи через `dataTransfer.setData`, использовать общий внутренний сервис состояния перетаскивания (`DragStateService`), гарантирующий 100% передачу идентификаторов перетаскиваемых файлов во всех браузерах.
     - Поддержать перетаскивание на пункт «Общий раздел» в левом сайдбаре для мгновенного копирования/перемещения.

2. **Чекбоксы (галочки) для мультивыделения:**
   - **В сетке (`app-file-grid`):**
     - Добавить круглый чекбокс в левый верхний угол каждой карточки папки и файла:
       - Визуально полупрозрачный при наведении курсора на карточку (`opacity: 0.6`).
       - Полностью активный и подсвеченный, если карточка выделена (`opacity: 1`).
     - Клик по чекбоксу переключает выделение только этого элемента без сброса остальных выделенных элементов.
   - **В таблице (`app-file-list`):**
     - Добавить первую колонку с чекбоксом в строку каждого файла и папки.
     - В заголовок таблицы (`<thead>`) добавить мастер-чекбокс «Выбрать все» / «Снять все».

3. **Ликвидация бага наложения панелей действий (Bulk Action Bar vs Mobile Action Sheet):**
   - В `drive-layout.component.ts`:
     - Скрыть `.mobile-action-sheet` на десктопе через CSS: по умолчанию `display: none;`, отображать только внутри `@media (max-width: 768px)`.
     - Унифицировать плавающий десктопный бар `.bulk-action-bar`:
       - Перевести все надписи на русский через `translate` pipe («Выбрано X», «Скачать архивом (ZIP)», «Переместить», «Копировать в Общий», «Удалить»).
       - Добавить в бар кнопку «Копировать в общий раздел».

4. **Модальное окно выбора области поиска («где конкретно искать»):**
   - Создать модальный компонент `search-scope-modal`:
     - Быстрые вкладки/кнопки: «Везде», «Личный диск (целиком)», «Общий раздел (целиком)».
     - Интерактивное дерево каталогов диска и общего раздела с чекбоксами для точечного выбора одной или нескольких конкретных папок.
     - Кнопка «Применить область поиска».
   - В строке поиска: вместо старого `<select>` отображать интерактивную кнопку-плашку с выбранной локацией (например: `Область: [Папка Документы] ▾`) с иконкой настроек области поиска.
   - Обновить фильтрацию поиска в сервисе: производить поиск с учетом выбранного массива `folderIds` или раздела.

## Этап 4. Локализация админки, кастомные дропдауны, единый стиль UI и Favicon

> **Цель этапа:** Перевести всю админскую панель на русский язык, внедрить кастомный компонент стеклянных выпадающих списков, выровнять геометрию интерфейса между разделами, добавить переход в общий раздел с экрана входа и обновить фавикон.

     - Здоровье системы и метрики серверов (`admin.health.*`).

     - `users-management.component.ts`
     - `storage-nodes.component.ts`

   - В диалоге редактирования ноды: добавить выбор единиц емкости (ГБ / ТБ), отображение физического размера диска и доступного места.

2. **Кастомный компонент стеклянного выпадающего списка (`GlassDropdownComponent`):**
   - Создать переиспользуемый компонент `GlassDropdownComponent` (`<app-glass-dropdown>`):

   - Добавить ссылки «Избранное» и «Корзина» в сайдбар общего раздела (`shared-space.component.ts`):
     - При клике перенаправлять на `/drive?tab=favorites` и `/drive?tab=trash`.
   - Унифицировать стили заголовков, хлебных крошек и шапок во всех лейаутах.

4. **Кнопка перехода в Общий раздел на экране логина:**

## Чеклист верификации реализации

| Модуль | Критерий успешности |
|---|---|
| **Ноды и квоты** | Админ может изменить лимит емкости ноды в ГБ/ТБ. Ошибка 400 не возникает, если файлы фактически помещаются на ноде. Нельзя выставить лимит больше реального диска. |
| **Копирование** | Клик «Копировать в общий раздел» копирует файл/папку в Shared без повторной загрузки данных (дедупликация блобов). Кнопка «Сохранить в личное» сохраняет файл в диск с контролем личной квоты. |
| **D&D** | Зажатием мыши файлы и папки надежно перетаскиваются в целевую папку без срывов и мерцания; событие сброса не вызывает загрузку файлов окна. |
| **Выделение** | На карточках и в строках таблицы работают галочки для выбора нескольких элементов без зажатия мыши или клавиш. |
| **Поиск** | Клик по выбору области поиска открывает модалку с деревом папок; поиск ищет только внутри выбранных директорий. |
| **Панель действий** | При выделении на десктопе появляется только одна аккуратная плавающая панель на русском языке, мобильная нижняя шторка не перекрывает ее. |
| **Админка** | Все страницы админки, формы, бейджи и подсказки отображаются на русском языке. |
| **Дропдауны** | Нигде в проекте нет стандартных HTML-селекторов — все списки используют стилизованный Glass Dropdown. |
| **Сайдбар** | При переходе между Личным диском, Общим разделом, Дашбордом и Админкой панель не прыгает по высоте, логотип одинаковый, кнопки избранного и корзины доступны. |
| **Экран входа** | Неавторизованный пользователь видит кнопку «Перейти в общий раздел» и может зайти в Shared Space в один клик. |
| **Git** | Все изменения собраны, протестированы и отправлены в GitHub-репозиторий. |
