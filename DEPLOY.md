# 🌌 Руководство по развертыванию Omega Cloud

Данное руководство описывает, как быстро и правильно задеплоить **Master-сервер** и распределенные **Storage-ноды (воркеры)**.

---

## ⚡ Краткий ответ: как устроено развертывание?

1. **Мастер-сервер готов к работе сразу**: в него уже встроен локальный диск (`Local Storage Driver`). После запуска мастера облако **уже полностью функционально** — можно загружать и скачивать файлы, создавать папки, пользователей и сессии.
2. **Вручную перекидывать тяжелые Docker-образы НЕ НУЖНО**:
   - На сервере Мастера всё собирается и запускается в одну команду скриптом или через Docker Compose.
   - Для удаленных нод (NAS / другие серверы) подготовлен генератор микро-пакета (`bundle`), который весит меньше 1 МБ. Вам не нужно тащить на NAS весь репозиторий с фронтендом и базой данных — достаточно скинуть этот компактный архив и запустить установщик.

---

## 1. Развертывание Master-сервера (Основной сервер)

Master-сервер включает в себя:
* **PostgreSQL 16** (база данных метаданных, VFS, квот и аудита)
* **ASP.NET Core API** (Control Plane, авторизация, SignalR, VFS, локальный сторидж)
* **Angular 19 SPA** (веб-интерфейс в стиле Apple Glassmorphism)
* **Caddy 2** (автоматический reverse proxy и бесплатный HTTPS/TLS)

### 🚀 Вариант А: Автоматический запуск скриптом (Рекомендуется)

#### На Linux / Ubuntu / Debian / macOS:
```bash
chmod +x scripts/deploy-master.sh
./scripts/deploy-master.sh
```

#### На Windows (PowerShell):
```powershell
.\scripts\deploy-master.ps1
```

Скрипт автоматически:
1. Проверит наличие Docker и Docker Compose.
2. Создаст файл `.env` из шаблона `.env.example`.
3. Сгенерирует надежные случайные пароли для PostgreSQL и криптографический JWT Secret.
4. Спросит ваш домен (или оставит `localhost` для локального тестирования).
5. Соберет и запустит контейнеры: `docker compose up -d --build`.
6. Дождется применения миграций базы данных и выдаст данные для входа.

---

### 🛠 Вариант Б: Ручной запуск через Docker Compose

Если вы предпочитаете настраивать всё вручную:

1. Скопируйте шаблон переменных окружения:
   ```bash
   cp .env.example .env
   ```
2. Откройте `.env` и настройте параметры:
   - `DOMAIN`: ваш боевой домен (например, `cloud.mycompany.com`) или `localhost`.
   - `CADDY_TLS`: ваш email для автоматического сертификата Let's Encrypt (или `internal` для самоподписанного сертификата).
   - `POSTGRES_PASSWORD`: задайте надежный пароль БД.
   - `JWT_SECRET`: задайте строку от 32+ символов.
3. Запустите сборку и стек контейнеров:
   ```bash
   docker compose up -d --build
   ```

### 🔑 Вход по умолчанию:
* **URL:** `https://localhost` (или `https://ваш-домен`)
* **Логин:** `admin`
* **Пароль:** `AdminPassword123!` *(смените в профиле сразу после первого входа!)*

## 2. Развертывание воркер-нод (Storage Nodes)

Подключать отдельные ноды нужно только если вы хотите расширить хранилище за счет внешних машин (домашний NAS Synology/TrueNAS, домашний ПК, второй сервер в другом ДЦ).

### 📦 Шаг 1. Сборка легкого пакета для ноды (на машине с репозиторием)

Чтобы не копировать на удаленный сервер весь тяжелый проект с `node_modules` и бэкендом, соберите микро-пакет:

#### На Linux:
```bash
chmod +x scripts/bundle-storage-node.sh
./scripts/bundle-storage-node.sh
```

#### На Windows:
```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\bundle-storage-node.ps1
```

Скрипт создаст компактный архив:
* `dist/omega-storage-node.tar.gz` (или `dist/omega-storage-node.zip`) — размер **менее 1 МБ**!

---

### 🌐 Шаг 2. Получение токена регистрации на Master-сервере

1. Войдите в веб-интерфейс Omega Cloud под учетной записью администратора.
2. В боковом меню перейдите в **Storage Nodes & Fleet** (или `/admin/nodes`).
3. Нажмите кнопку **«Generate Node Token»**.
4. Скопируйте сгенерированный одноразовый ключ (например, `node_reg_abc123...`).

---

### 💻 Шаг 3. Установка и запуск на удаленной машине / NAS

1. Скопируйте архив `omega-storage-node.tar.gz` (или zip) на целевую ноду:
   ```bash
   scp dist/omega-storage-node.tar.gz user@your-nas:/opt/
   ```

2. На целевой ноде распакуйте его:
   ```bash
   cd /opt
   tar -xzf omega-storage-node.tar.gz
   cd omega-storage-node
   ```

3. Запустите установщик:
   ```bash
   chmod +x install-node.sh
   ./install-node.sh
   ```
   *(или `.\install-node.ps1` если нода на Windows)*

4. Установщик в интерактивном режиме запросит:
   - **Адрес Master-сервера**: например `https://cloud.mycompany.com` (или локальный IP мастера `http://192.168.1.100:5000`)
   - **Registration Token**: вставьте токен, полученный на Шаге 2.
   - **Имя ноды**: например, `NAS-Storage-Office`.
   - **Публичный адрес / NAT**: если у ноды есть белый IP/домен — укажите его для прямых скачиваний на полной скорости; если нода дома за NAT — просто нажмите Enter (мастер будет автоматически проксировать трафик).

Нода запустится в Docker, зарегистрируется на Мастере, сохранит полученные учетные данные в `node-state.json` и начнет отправлять телеметрию каждые 15 секунд.

В панели администратора статус ноды сразу изменится на **Online** 🟢 с отображением свободного места и графиков нагрузки.

---

## 3. Альтернатива: Офлайн-перенос Docker-образа (если на ноде нет интернета)

Если ваш удаленный NAS не имеет доступа в интернет для сборки `.NET` контейнера:

1. **Соберите образ на мастере / рабочем ПК:**
   ```bash
   docker build -t omega-storage-node:latest backend/src/Omega.StorageNode
   ```
2. **Экспортируйте образ в tar-файл:**
   ```bash
   docker save omega-storage-node:latest | gzip > omega-storage-node-image.tar.gz
   ```
3. **Перенесите файл на ноду и загрузите:**
   ```bash
   docker load < omega-storage-node-image.tar.gz
   ```
4. После этого в `docker-compose.yml` ноды замените секцию `build: .` на `image: omega-storage-node:latest` и выполните `docker compose up -d`.

## 4. Полезные команды для обслуживания

### Просмотр логов:
```bash
# Логи мастера
docker compose logs -f backend
docker compose logs -f caddy

# Логи ноды
docker compose logs -f storage-node
```

### Перезапуск сервисов:
```bash
docker compose restart
```

### Остановка стека:
```bash
docker compose down
```

### Где хранятся данные:
* **Файлы пользователей (Master):** `./data/storage`
* **Файлы пользователей (Нода):** `./data/storage` на ноде
* **База данных PostgreSQL:** `./data/postgres`
* **SSL-сертификаты Caddy:** `./data/caddy`
